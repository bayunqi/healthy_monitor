HealthyMonitor

LLM-powered personal health assistant for Apple ecosystem — built for programmers who sit too long.

Platform macOS + iOS + watchOS
Stack Swift / SwiftUI / Claude API
Phase 1 Target macOS menu bar MVP
North Star Pain score trending down in 8 weeks

Vision & Pain Points

North Star: "The app that made me actually stand up" — measurable behavior change, not just notification delivery. If the user's back pain score doesn't trend down within 8 weeks of consistent use, something is wrong with the product.

Most health reminder apps fail because they are annoying and generic. They fire at rigid intervals, never learn from behavior, and become background noise within days.

HealthyMonitor wins by being adaptive: it learns your schedule, your compliance patterns, and your pain points — then adjusts. The LLM coach feels like a knowledgeable colleague who checks in, not a nagging alarm.

Who is this for?

💻
Programmers & desk workers
8+ hours/day at a desk, often forgetting to stand, drink water, or stretch.
🍎
Apple ecosystem users
Mac + iPhone + Apple Watch as daily tools. Notifications across all devices.
🤕
Chronic pain sufferers
Lower back, neck, wrist pain from poor posture and insufficient movement.
🧠
Self-improvers
Want data on their behavior, not just reminders — trend visibility matters.

User Journey

Day 0 — First Launch
LLM Onboarding Conversation
The coach introduces itself in 1–2 sentences and asks 5–7 natural questions: current pain symptoms, work hours, water goals, reminder style preference, quiet hours. At the end, it confirms the personalized plan and starts the heartbeat engine.
Daily Use — Steady State
The Reminder Loop
Every N minutes: notification on Mac menu bar + Watch haptic (+ optional iPhone banner). User taps "Done" or raises wrist. Log entry created. Compliance ring updates. Occasionally the coach adds a brief contextual note.
Sunday Evening
Weekly Coaching Summary
Coach sends a notification with a brief insight: "You drank water 73% of the time but only stretched 31% on Thursdays." Tapping opens a coaching chat with one actionable suggestion and a pain score check-in.
Week 2+ — Adaptation
Intelligent Schedule Adjustment
LLM detects patterns in compliance data. Uses tool calls to adjust reminder intervals. If you snooze stretch reminders 80% of the time on Friday afternoons, it shifts them to Thursday or reduces frequency.
Week 8
Health Outcome Measurement
Coach reviews 8 weeks of pain scores. If trending down with >60% compliance: the app is working. If not: adjust exercise types, reminder intervals, or conversation approach.

Data Models

// HealthProfile — Swift Data + CloudKit
@Model final class HealthProfile {
    var userId: String
    var painPoints: [String]          // ["lower back", "neck"]
    var workScheduleStart: Date       // 09:00
    var workScheduleEnd: Date         // 18:00
    var quietHoursStart: Date?
    var quietHoursEnd: Date?
    var reminderStyle: ReminderStyle  // .gentle | .firm | .silentOnlyWatch
    var waterGoalMl: Int              // 2000
    var llmConversationHistory: Data  // last 50 messages, serialized
    var onboardingCompleted: Bool
    var lastWeeklyPainScore: Int?     // 1–10
}

// ReminderConfig — local only (per device)
@Model final class ReminderConfig {
    var type: ReminderType            // .stand | .water | .stretch | .exercise
    var intervalMinutes: Int          // 45
    var isEnabled: Bool
    var lastFiredAt: Date?
    var nextScheduledAt: Date?
}

// ActivityLog — Swift Data + CloudKit
@Model final class ActivityLog {
    var id: UUID
    var reminderType: ReminderType
    var scheduledAt: Date
    var respondedAt: Date?
    var response: ActivityResponse    // .completed | .skipped | .snoozed | .missed
    var deviceSource: String          // "mac" | "iphone" | "watch"
}

// DailyStats — computed from ActivityLog queries
struct DailyStats {
    let date: Date
    let totalReminders: Int
    let completed: Int
    var complianceRate: Double { Double(completed) / Double(totalReminders) }
    let byType: [ReminderType: Int]
}

Notification Architecture

macOS Menu Bar App (always running)
  └── UNUserNotificationCenter — schedules all local notifications
       ├── Action: "Done ✓"   → ActivityLog.response = .completed
       ├── Action: "Skip"     → ActivityLog.response = .skipped
       └── Action: "Snooze"   → reschedule +10 min, increment snoozeCount

iPhone (optional, for users with phone nearby)
  └── UNUserNotificationCenter — independent local schedule
       └── UNNotificationContentExtension — rich notification UI

watchOS (forwarded from iPhone via WatchConnectivity)
  └── WKUserNotificationHostingController
       └── Haptic feedback + single-tap confirm
       └── Complication updates via CLKComplicationDataSource

MVP Decision: Local notifications only — no Apple Push Notification Service. The macOS menu bar app is the authoritative scheduler (it's always running). This eliminates all server infrastructure costs while delivering identical UX.

Testing Strategy

Guiding principle: Every test layer answers the same question — "Is the user's health actually improving?" Unit tests verify correctness; behavioral KPIs verify outcomes.

Layer 4: Behavioral KPIs — Pain score, compliance rate, engagement
Layer 3: LLM Quality Tests (weekly) — Golden-set, tool use accuracy
Layer 2: Integration Tests — Full remind → confirm → log E2E cycle
Layer 1: Unit Tests — ReminderEngine, ActivityLogger, LLMService

Layer 1 — Unit Tests (every PR)

  • testStandReminderFiresAfter45Minutes()
  • testWaterReminderDoesNotFireDuringQuietHours()
  • testSnoozeDelaysNextReminderByConfiguredDuration()
  • testReminderEngineResumeAfterAppRestart()
  • testCompletedActivityWritesToPersistence()
  • testDailyStatsComplianceRateCalculation()
  • testOnboardingExtractionUpdatesHealthProfile() (mocked API)
  • testPromptCachingBreakpointsAreCorrect()

Layer 2 — Integration Tests (every PR)

The core E2E cycle:

1. Schedule reminder 5 seconds in the future
2. Wait for notification delivery (assert within 6 seconds)
3. Simulate "Done" action tap
4. Assert: ActivityLog entry exists with response = .completed
5. Assert: next reminder is scheduled
6. Assert: DailyStats compliance rate reflects the completion

Also test: skip, snooze, missed-grace-period, CloudKit sync latency <30s.

Layer 3 — LLM Quality Tests (weekly, not per-PR)

  • testOnboardingExtractsPainPointsCorrectly() — given natural language → verify structured profile
  • testCoachDoesNotGuiltTripMissedReminders() — assert no guilt language on 5 missed reminders
  • testAdaptiveIntervalDecreaseForLowCompliance() — verify tool call fires when 30% compliance
  • testWeeklyInsightContainsSpecificData() — coach must cite actual numbers from logs
